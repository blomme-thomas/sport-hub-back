# Glossaire

Langage commun du domaine. Les termes DDD/hexagonaux (Aggregate, Port, Adapter, etc.) sont définis dans `instructions/00-glossary-and-artifacts.instructions.md`. Les termes ci-dessous sont ceux du code livré ; le vocabulaire de la génération de séances est partiellement couvert (voir les dernières lignes).

| Terme | Définition | Dans le code |
|---|---|---|
| Activité | Séance d'activité physique enregistrée par Garmin et copiée dans la base locale. Porte un identifiant Garmin, un type, une date de début, une durée, une distance facultative et le contenu source Garmin. | Entity `Activity` (`garmin-sync`), table `activities` |
| Type d'activité | Libellé du sport tel que Garmin le renvoie (`typeKey`). Texte libre, sans liste fermée. | `Activity.type` |
| Identifiant Garmin | Identifiant de l'activité côté Garmin. Sert de clé d'idempotence : une même activité Garmin n'existe qu'une fois en base. Distinct de l'identifiant interne (UUID). | Value Object `GarminActivityId` |
| Synchronisation | Import dans la base des activités Garmin nouvelles ou modifiées. Déclenchée à la main pour l'instant, rejouable sans doublon. | Use case `SyncGarminActivities` |
| Dernière activité connue | Activité enregistrée dont la date de début est la plus récente. Point de reprise de la synchronisation. | `findLatestStartedAt()` |
| Fenêtre de recouvrement | Période relue à chaque synchronisation : elle commence 7 jours avant la dernière activité connue, pour rattraper les modifications récentes côté Garmin. Sans activité connue, il n'y a pas de borne et l'historique remonte à 365 jours. | Value Object `SyncWindow` |
| Activité créée | Activité Garmin dont l'identifiant n'est pas encore en base. Compteur `created`. | Résultat de la synchronisation |
| Activité mise à jour | Activité déjà en base, dont le contenu Garmin a changé. Compteur `updated`. | Résultat de la synchronisation |
| Activité ignorée | Activité déjà en base, dont le contenu est identique. Elle n'est pas réécrite. Compteur `ignored`. | Résultat de la synchronisation |
| Activité invalide | Activité Garmin dont le format ou les valeurs ne respectent pas les règles : elle est sautée et journalisée, sans être comptée. | `InvalidActivityError`, adapter Garmin |
| Clé Garmin Personal | Secret créé par l'utilisateur dans Garmin Connect, échangé contre un jeton d'accès. Variable `GARMIN_PERSONAL_API_KEY`. Elle expire (30 jours à 1 an selon le choix de l'utilisateur). | `GarminPersonalApiTokenProvider`, voir [API Garmin Personal](../technique/garmin-personal-api.md) |
| Jeton d'accès Garmin | Jeton valable 24 heures, renouvelé automatiquement 60 secondes avant son expiration. Jamais journalisé ni renvoyé. | `GarminPersonalApiTokenProvider` |
| Accès Garmin refusé | Erreur `GARMIN_ACCESS_DENIED` (502) : clé absente ou refusée, ou jeton refusé. | `GarminAccessDeniedError` |
| Garmin indisponible | Erreur `GARMIN_UNAVAILABLE` (503) : panne, délai dépassé ou réponse inattendue de Garmin. | `GarminUnavailableError` |
| Statistiques d'entraînement | Volume de séances agrégé par période (nombre de séances, durée totale, distance totale), pour l'ensemble des activités ou pour un type, avec la période précédente et la variation. Calculées à la demande depuis les activités synchronisées, rien n'est stocké. | `GET /api/stats`, `GetTrainingStatsUseCase`, `TrainingStatsCalculator` (`training-stats`) |
| Période | Intervalle de temps de calcul, toujours complet : soit une semaine ISO (du lundi 00:00:00.000 UTC au dimanche 23:59:59.999 UTC), soit un mois calendaire UTC. Une activité appartient à une seule période, celle qui contient sa date de début. | Value Object `StatsPeriod` (granularité `week` ou `month`) |
| Plage de périodes | Ensemble des périodes complètes qui intersectent les dates `from` et `to` demandées. Limitée à 104 périodes. | Value Object `StatsRange` ; erreur `STATS_RANGE_TOO_LARGE` |
| Période précédente | Période de même granularité immédiatement antérieure à la période courante (la semaine précédente, ou le mois précédent, y compris au changement d'année). Sert de référence à la variation. | `StatsPeriod.previous()`, champ `previous` de la réponse |
| Volume | Ensemble de trois mesures d'une période : `count` (nombre de séances), `durationSeconds` (somme des durées), `distanceMeters` (somme des distances). Une séance sans distance compte pour zéro mètre, mais reste comptée en nombre et en durée. | Value Object `ActivityVolume` |
| Variation | Écart entre la période courante et la période précédente, pour chaque mesure du volume : `absolute` (courant moins précédent) et `percent` (écart relatif arrondi à une décimale, `null` si la période précédente vaut zéro). | Value Object `VolumeVariation` |
| Séance générée | Séance d'entraînement produite par Claude (titre, résumé, étapes, durée totale), validée par les invariants de la Entity avant d'être renvoyée. Non persistée. | Entity `GeneratedWorkout` (`workout-generation`), `POST /api/workouts/generate` |
| Étape | Partie d'une séance générée : ordre à partir de 1, libellé, durée entière en minutes, intensité (`easy`, `moderate`, `hard`) et notes facultatives. | Value Object `WorkoutStep`, `WorkoutIntensity` |
| Contexte récent | Statistiques de volume des dernières semaines complètes, transmises à l'IA pour concevoir la séance. Une semaine sans activité figure à zéro. | `RecentTrainingContext`, port `IRecentTrainingContextProvider` |
| Créneau | Plage saisie par l'utilisateur dans son calendrier : un jour, une heure de début et une heure de fin (même jour, fin strictement postérieure au début), un type (libre ou occupé) et une récurrence. Les heures sont des heures murales locales. Les créneaux peuvent se chevaucher. | Entity `Slot` (`creneaux`), `POST /api/slots` |
| Libre | Type de créneau `libre` : plage pendant laquelle l'utilisateur est disponible. | Valeur `libre` de `SlotType` |
| Occupé | Type de créneau `occupe` (sans accent dans le contrat) : plage pendant laquelle l'utilisateur est indisponible. | Valeur `occupe` de `SlotType` |
| Récurrence | Règle de répétition d'un créneau. `aucune` : ponctuel (défaut). `hebdomadaire` : même jour de la semaine et même heure, sans date de fin. Il n'existe pas d'exception par occurrence : modifier ou supprimer vaut pour toute la série. | Value Object `SlotRecurrence` |
| Occurrence | Jour concret d'un créneau, obtenu en le développant sur une période. Un créneau hebdomadaire a une occurrence par semaine à partir de sa date d'ancrage. Rien n'est stocké. | Value Object `SlotOccurrence`, `Slot.occurrencesIn()`, champ `items` de `GET /api/slots` |
| Heure murale locale | Heure telle qu'elle est saisie et affichée (`HH:mm`), sans conversion en instant UTC. Le fuseau IANA (`timeZone`) est une métadonnée, `Europe/Paris` par défaut, qui ne sert jamais à calculer. Aucune gestion des changements d'heure. | Value Objects `LocalTime`, `SlotTimeZone` |
| Période de lecture | Intervalle de jours calendaires `from` à `to` (`YYYY-MM-DD`), bornes incluses, de 366 jours au plus, pour lequel `GET /api/slots` renvoie les occurrences. Distincte de la « Période » des statistiques, qui désigne une semaine ou un mois complets en UTC. | Value Object `SlotPeriod` |
| Objectif | Ce que l'utilisateur prépare : un titre (200 caractères au plus), un type, une date cible facultative et, pour un événement, un format et un temps cible. Créé, modifié et supprimé à tout moment, sans contrainte de date. | Entity `Goal` (`objectifs`), table `goals`, `/api/goals` |
| Type d'objectif | Nature de l'objectif : `evenement`, `volume` ou `regularite`. Seul le type `evenement` peut porter un format et un temps cible. | Value Object `GoalType` (`GOAL_TYPES`) |
| Événement | Objectif de type `evenement` : une épreuve prévue à une date donnée (par exemple un triathlon), décrite par un format et, facultativement, un temps cible. | Valeur `evenement` de `GoalType` |
| Format | Format d'un événement : `sprint`, `olympique`, `half`, `full` ou `autre`. Réservé au type `evenement`, facultatif, modifiable. | Value Object `EventFormat` (`EVENT_FORMATS`), champ `eventFormat` |
| Temps cible | Durée visée pour un événement, en secondes : entier de 1 à 2147483647, facultatif, modifiable (une valeur `null` l'efface). Réservé au type `evenement`. | Value Object `TargetTime`, champ `targetTimeSeconds` |
| Objectif à venir | Objectif dont la date cible est aujourd'hui (jour UTC) ou postérieure. Un objectif sans date cible n'est jamais à venir. | `Goal.isUpcoming()`, `GET /api/goals?upcoming=true` |
| Discipline | Type d'activité tel que Garmin le fournit (clé de type), associé à un libellé lisible que l'utilisateur peut modifier, et à deux dates : première et dernière synchronisation ayant reçu ce type. Créée automatiquement par la synchronisation ; le libellé provisoire est la clé elle-même. Ne se confond pas avec la « Clé Garmin Personal » (secret d'accès). | Entity `Discipline` (`disciplines`), table `disciplines`, `/api/disciplines` |
| Référentiel des disciplines | Ensemble des disciplines connues, avec leurs libellés. Alimenté uniquement par la synchronisation Garmin, par ajout de nouvelles clés ; le renommage est la seule modification possible. Les dates d'une discipline sont des instants de synchronisation, pas des dates d'activité. | Module `disciplines`, `IDisciplineRepository` |
| Séance planifiée | Séance prévue à une date donnée, dans une discipline du référentiel, avec une durée totale, un statut, du matériel et des points d'attention facultatifs, et une liste ordonnée de modules. Créée à la main ou par l'IA, modifiable librement. | Aggregate `Session` (`seances`), tables `sessions` et `session_modules`, `/api/sessions` |
| Module | Partie ordonnée d'une séance planifiée : type (échauffement, éducatifs, séries, retour au calme ou autre), durée, consigne, zones cibles facultatives (fréquence cardiaque, allure ou puissance) et effort perçu visé facultatif. Sa position est son rang dans la séance, de 1 à n. | Value Object `SessionModule`, `MODULE_TYPES` (`seances`) |
| Statut de séance | État d'une séance planifiée : `planifiee` à la création, puis `realisee` ou `manquee`. Une séance `realisee` ne peut plus être modifiée. | Value Object `SessionStatus` (`SESSION_STATUSES`) |
| Modifiée manuellement | Indicateur d'une séance dont l'utilisateur a changé un champ ou la liste des modules. Passe à vrai à la première modification réelle et ne revient jamais à faux. Chaque modification est journalisée (date, champ, valeur précédente). | Champ `modifiedManually` de l'Aggregate `Session`, table `session_change_logs` |
| Créneau disponible | Durée restante d'un créneau libre une fois retirés les créneaux occupés qu'il chevauche et les séances fixes du même jour. Calculée à la demande, jamais stockée, et nulle pour un créneau dont la date est passée. | `ComputeFreeSlotCapacityUseCase`, `FreeSlotCapacityDto` (`planification`) |
| Placement | Opération qui répartit des séances dans les créneaux libres d'une période, à partir des créneaux disponibles. Le calcul de la capacité restante est local, sans IA. | `computeFreeSlotCapacity` (`planification`) |
| Séance fixe | Séance dont la place ne doit plus bouger pour le placement : statut `realisee` ou `manquee`, ou séance modifiée manuellement. Elle consomme la durée des créneaux libres de son jour ; une séance planifiée non modifiée ne consomme rien. | Règle du calcul de capacité (`planification`), champs `status` et `modifiedManually` de `Session` |
| Rapprochement | Association entre une séance planifiée et une activité réalisée du même jour et de la même discipline. Automatique seulement quand il n'existe qu'une séance et une activité candidates ; sinon il reste en attente, et l'utilisateur peut le faire manuellement. Une activité ne peut être rapprochée que d'une seule séance. | `ReconcileSessionsUseCase`, `POST /api/sessions/reconcile`, `PUT /api/sessions/:id/activity` (`seances`) |
| Activité réalisée | Activité Garmin synchronisée, liée à une séance par un rapprochement. Une séance liée passe à réalisée et ne porte qu'une activité. | Table `session_activity_links`, champ `activity` de la séance (`seances`) |
| Planning | Ensemble des séances proposées par l'IA pour une période, créées directement dans les créneaux libres. Les séances existantes ne sont jamais déplacées. | `GeneratePlanningUseCase`, `POST /api/planning/generate` (`planification`) |
| Génération de planning | Un appel unique au modèle qui propose le planning d'une période. Le contenu envoyé ne contient que le temps libre, les séances existantes, le référentiel et l'objectif ; aucune donnée Garmin brute. | `ClaudePlanningGeneratorAdapter` (`planification`) |
| Période de planification | Plage de jours calendaires, du premier jour au dernier (ou à la date cible d'un objectif), bornes incluses, sans dépasser 366 jours. Les jours passés sont écartés. | Règle de `GeneratePlanningUseCase` (`planification`) |
